Amazon's 16 Leadership Principles

Every interview question maps back to one or more LPs. Prepare at least one STAR story for each.

Behavioral — STAR Method

Be specific. Use "I", not "we". Always quantify the result. Expect follow-up probes on every answer.

STAR: Situation (brief context) → Task (your specific role) → Action (what YOU did, step by step) → Result (quantified outcome + what you learned)

System Design

You won't write code, but you'll drive the design conversation. Know trade-offs, failure modes, and AWS services at Amazon scale.

TPM Design Framework:
  • Clarify requirements (functional vs non-functional, scale, SLA)
  • Back-of-envelope estimation (DAU × actions = QPS, storage needs)
  • High-level architecture → deep dive on bottlenecks
  • Trade-offs: SQL vs NoSQL, sync vs async, consistency model
  • Failure modes + monitoring (what breaks, how you detect it)

Program Management

Own delivery from kickoff to launch across teams with no direct authority. Show you can navigate ambiguity at scale.

Working Backwards: Press Release → FAQ → Visuals → 6-pager narrative. Start with the customer outcome, work back to the engineering plan — not the other way around.

Product Sense

Start with the customer. Use CIRCLES for design questions. Tie every answer back to customer obsession.

CIRCLES: Comprehend → Identify the customer → Report needs → Cut to priority → List solutions → Evaluate trade-offs → Summarize recommendation
